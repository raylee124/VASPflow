# 远程 VASP 执行约定

## 六阶段工作流

首次完整计算依次执行以下阶段；继续已有任务时读取私人记录和 manifest，只补充缺失项。可在同一轮集中询问相邻阶段的必要信息，不能跳过未获得的批准。先提供已有设置摘要，避免重复盘问。

### 1. SSH 连接

按 setup.md 在用户本机独立终端收集连接参数，默认只向 agent 提供别名及连接状态，不在聊天索取 IP/账号/密码。明确提醒：如果依赖内网穿透、Tailscale、VPN、端口转发或跳板机，用户需自行完成网络设置并保持连通后再连接。原生 SSH 验证主机身份与认证，失败时先本地诊断，不自动回传原始连接日志，不声称已接入。

### 2. 定义工作区

登录成功后询问允许访问哪些目录、分别允许读还是写，并选择本次输出目录。保存多个 `workspaces`，每项包括 canonical_path、read、write、confirmed_at 和 user_statement；只读模板库/势库与输出目录分开。旧 `remote_work_root` 仅为兼容字段，不能凭字段存在推断授权。

对用户指定路径检查规范绝对路径、符号链接、目录遍历权限、实际读/写能力和配额；不要遍历未授权的全部 home。新建目录验证最近的既有父目录。操作系统允许访问不代表用户允许，用户允许也不保证 OS 有权限；仅使用两者交集。不为通过检查而自动 chmod 或提权。无写权限时准备本地草稿并报告阻碍。

### 3. 输入文件模式

- **基于参考：**取得用户指定的参考目录/文件，核实计算目标及哪些设置需要保留；读取参考并记录哈希，不改写源文件。解释与本任务不兼容的设置，提供差异与修改理由。部分参考文件缺失时只补缺项，不要求重交全部文件。
- **从零创建：**取得 POSCAR/CIF 等结构，或能明确生成结构的晶格、组分、坐标等信息；明确任务、维数、磁序、泛函及相关方法选择。从零不意味着凭空猜结构、U 值或收敛参数。

记录 `reference` 或 `from_scratch` 模式。发现任务和已记模式冲突时询问本次例外，不覆盖长期偏好。优先按 tools.md 使用 VASPKIT 等合适工具，然后独立验证生成结果。

### 4. 提交脚本模式

此阶段必须明确询问：“请提供这台机器上成功使用过的提交脚本，或给出我获准读取的脚本路径；如果没有，请说明任务管理系统和机器情况。若是个人 PC，将采用直接 mpirun。”用户已提供或当前私人档案有已确认的适用模板时复用，只询问缺项。不要求把服务器地址/账号贴到聊天。

没有脚本时集中问清：

| 运行环境 | 必要信息 |
|---|---|
| Slurm、PBS/Torque/OpenPBS/PBS Pro、LSF、SGE 或其他集群 | 管理系统及站点用法、分区/队列、计费账户（如适用）、节点/核/GPU/内存/时限、MPI 启动方式、VASP 路径及 module/初始化方式 |
| 个人 PC / 无调度器的专用工作站 | 确认该机器用于直接计算；Linux/WSL 环境、MPI 与 VASP 路径/版本、允许核数和线程数、内存与时限、并发上限和断线保持方式；采用 mpirun |
| 不清楚 | 在授权范围做轻量只读探测，并由用户/管理员确认机器角色；找不到 sbatch/qsub 不能推断可直接计算 |

`execution_mode`（scheduler/direct）与 `script_mode`（reference/from_scratch）分开记录。个人 PC 不创建虚构队列或调度器 ID；已明确个人 PC 时无需再索取队列。若用户称个人 PC 但发现站点调度器或共享资源限制，先解释矛盾再确定执行方式。非 Linux 原生环境不能直接假定可运行 Linux VASP。

- **基于参考：**读取成功脚本，记录来源和哈希，核实 scheduler、account、queue、module、MPI、可执行文件及资源参数在当前服务器仍适用；保存差异，不直接运行未经检查的参考脚本。
- **从零创建：**根据已确认执行模式和环境生成脚本，询问不能发现的账户/队列/预算；个人 PC 以 [run-direct.sh](../assets/run-direct.sh) 为最小模板，填入已验证的参数和实际环境初始化。不得猜分区名、VASP 路径或核数。调度器环境优先采用站点成功案例，不能把 Slurm 模板强套给 PBS/LSF/SGE。

脚本模式与输入模式独立，支持四种组合。明确每任务和全批次的节点/核/GPU、内存、时长、并发与作业数量上限。资源消耗估计注明假设，不把 walltime 上限当成准确运行时长。还应列出任务依赖、失败处理和允许的重试次数。

### 5. 计划与具体文件预览

先确认工作内容、结果目标与关键物理假设，然后在已允许的目录生成草稿，形成 `plan.md` 与输入/作业文件。计划至少包含方法、输入来源、目录布局、工具及环境、任务数量和依赖、资源上限、验证标准、后处理输出与当前缺失项。科学公式采用 LaTeX。

向用户同时提供计划和以下预览，而不是只提出“是否开始”：

| 文件 | 预览要求 |
|---|---|
| POSCAR | 晶格、元素顺序/数量、坐标类型、约束及代表坐标；大文件提供完整文件链接并注明节选 |
| INCAR | 实际拟运行参数，及参考模式中的重要差异/理由 |
| KPOINTS | 实际网格或路径、权重/偏移等；若明确使用 KSPACING，展示该设置并注明不生成 KPOINTS，不为凑四份文件制造冲突 |
| POTCAR | 仅 TITEL 等必要标识、势变体/顺序、泛函/版本和哈希；不展示完整受许可内容；未取得合法势文件时明确标记未完成并阻止提交 |
| 提交脚本 | 实际脚本内容，包括资源、初始化、运行路径、启动命令和日志位置 |

对高通量/四态文件组展示每类不同输入族的一套代表文件，以及完整任务索引、任务总数、参数差异表、生成规则与依赖。四态需展示四个自旋配置的差异、目标原子编号和镜像审计，不能只展示一个态而隐藏其余态。所有实际文件均保留可审阅路径，代表性预览不能替代全批次校验。

保存计划版本、全批次输入/脚本哈希和任务索引。等待用户审阅和确认提交该版本；可将计划批准与该批次提交许可合并成一次确认，不要求重复点击。若仅批准科学方案而未批准提交，则不得推断提交许可。等待期间可做只读验证，不能提前提交。

用户要求修改时更新草稿和差异，再呈现修改后的结果。批准后更改物理参数、势、输入/脚本内容、资源、任务数或输出目标，必须重新审阅变更。仅 job ID、日志、状态等运行元数据变化不触发重审。记住习惯或以前批准的另一个批次都不能替代此次审阅。

### 6. 提交、验收与后处理

按下文执行：提交前核对批准版本和实际哈希，对全批次逐目录校验；只提交批准清单内的任务。记录 job ID、状态和失败证据。完成后先判断可用性，再使用 VASPKIT 等工具处理结果，最后交付结果表、图、脚本及来源。长任务可报告“已提交/仍运行”，不能报告“计算完成”。后续从 manifest 恢复，不重复提交。

## 环境档案与权限复用

SSH 只解决登录，不能决定泛函、磁序、势文件、资源预算。首次从用户现有成功算例发现环境，保存版本和路径；每次会话做轻量检查。不要在未验证环境下运行第三方一键安装脚本。

配置中的 `authorization` 是用户认可范围的记录；脚本没有实现权限隔离。首次授权后不重复问相同目录/连接问题，但新批次仍按阶段 5 审阅具体计划与文件。超范围只询问新增部分。保留未知字段为 `null`，不要把示例值当成用户授权。新的明确用户指令优先。

## 输入准备

1. 确定任务类型：结构优化、静态、能带、DOS、SOC、DFT+U、NEB 或磁交换等。缺少会改变物理模型的信息时先询问；非关键选择写明假设。服务器档案与具体材料的计算参数分开保存。
2. 检查 POSCAR 的晶格、坐标单位、元素顺序、原子数、选择性约束和周期维数。检查源结构是否来自已收敛优化。
3. 根据目标与收敛证据选择泛函、ENCUT、采样、展宽、电子/离子阈值、磁性、SOC 和 U 参数。未知参数查对应版本的 [VASP 文档](https://vasp.at/wiki/index.php/Input)。不把一套通用 INCAR 宣称为所有材料的正确输入；不盲用其他技能的固定并行参数。
4. 在服务器许可目录内组装 POTCAR；独立核实物种顺序、势的具体变体、泛函、版本及校验和，只记录必要元数据。禁止从公开仓库获取未授权势文件、打印整份 POTCAR 或把它打包发布。
5. 明确选择 KPOINTS 或 KSPACING，检查冲突；核实 MAGMOM/M_CONSTR 长度、共线/非共线形式及相关选项。由实际网格、核数和可执行文件确定并行设置。
6. 创建新的计算目录，例如 `material/relax/run-20260908-001`；检查目录未存在后创建，不复用一个已在运行的目录。准备输入、站点适配的作业脚本和 `run-manifest.json`。可变参数集中在生成脚本开头。
7. 对源文件与上传文件核对 SHA-256；检查脚本 shebang、LF 换行、可执行路径、MPI/module 环境和配额。校验失败不提交。

VASP 基础输入关系见 [官方输入说明](https://vasp.at/wiki/index.php/Input)。复杂任务优先调用已安装且适用的科学工具；首次使用 pymatgen、ASE 或 VASPKIT 时核实服务器版本与接口，不要求整套工具全装齐。

## 提交与断线恢复

- 集群采用站点调度器，不在登录节点直接运行 VASP。已确认个人 PC 则用 `mpirun -np <approved_ranks> <verified_vasp>`，不要求安装调度器。先核实 MPI 与该 VASP 构建兼容、rank 数乘线程数不超核预算，并检查正在运行的自身任务和内存余量；不默认全部核、oversubscribe 或 allow-run-as-root。
- 个人 PC 先完成并审阅 run-direct.sh 中的参数/初始化，保存哈希，再通过已有 tmux 或站点认可的持久会话启动。tmux 不改变实际 mpirun 启动方式；没有 tmux 时明确前台断线风险或选择已可用的持久方式，不能擅自安装。模板包含一次性启动锁、日志、PID/启动时间、退出码和 GNU timeout 时限；先验证 GNU timeout 可用及本机 MPI 对终止信号的响应。缺少 exit-code 文件不代表成功，PID 存在也可能被复用，必须核对启动身份/工作目录。普通 PC 的内存约定不是硬配额；确需硬限制时使用已配置的 cgroup/管理员策略，不能宣称模板实现了隔离。
- 作业模板来自该服务器成功案例。没有模板时先发现队列、账户与资源策略，再生成适配模板；不能因为有 `sbatch` 就猜测可用分区和核数。
- Slurm：在确定的运行目录调用 `sbatch --parsable job.sh`，记录返回的作业号（可能带 `;cluster` 后缀）。使用 `squeue` 检查排队状态，`sacct` 检查完成状态/退出码；某些站点没有 accounting 或记录延迟，此时状态标记未知。参考 [sbatch 官方文档](https://slurm.schedmd.com/sbatch.html)。
- PBS：使用 `qsub job.sh`，保留完整作业 ID（包括服务器后缀），使用站点版本支持的 `qstat` 选项；不要拿 Slurm 参数套用。
- 提交前在 manifest 写入唯一运行标识、工作目录、时间和 `submitting` 状态；提交成功立刻存下 job ID。提交命令 SSH 超时可能意味着服务器已接收，不能自动再次提交。通过用户、唯一作业名、工作目录、时间及日志核对；不能确定时标记 `submission_unknown` 并停下提交。
- 多个 agent/终端可同时提交时，调度器提交前也必须在该运行目录原子创建一次性提交标记（例如 mkdir），保存返回输出。已有标记则查询状态，不再次提交；标记不能因 SSH 断开或客户端异常而自动删除。个人 PC 的模板自带一次性锁，但调度器提交也需要此保护。明确失败后的重试使用新目录和已授权修订。
- 重试需记录原因，在新目录生成修复版本。超出已授权重试/作业数量预算时不继续。不得只为成功结束而放宽科学收敛标准。
- 连接中断不等于调度器作业停止；重新连接后用 job ID 恢复。取消仅针对用户要求或已授权规则下的自身作业，并记录原因。

## 后处理

1. 区分排队、运行中、程序结束、电子收敛、离子收敛和参数收敛。优化需按任务检查力/应力、停止原因和限制条件；静态计算不要求离子优化收敛。文件存在、达到最大步数或 Slurm COMPLETED 都不能单独证明科学有效。
2. 读取必要的 OUTCAR、OSZICAR、vasprun.xml、CONTCAR、调度器日志。大型数据留在服务器处理，只回传摘要和需要的图。解析失败和文件截断应明确报告，不把失败填成零值。
3. 比较能量时统一能量定义、体系归一化、泛函、势、截断和采样精度；说明采用自由能还是零展宽能量。不要把未收敛计算混入能量差。
4. 能带/DOS 标明能量参考、自旋通道和单位；电荷差分先核实晶胞、坐标和网格的一致性。使用 VASPKIT 前核实版本、所需文件和任务菜单序列；保存实际输入菜单与输出校验。输出图具有轴标签和图例。
5. 将结果表、图、分析脚本和结论存放在当前任务内；有用的检查程序放到 `TEST`，清理仅本次生成且无后续价值的临时文件。

## 四态磁交换的专门要求

仅在四态磁交换任务应用以下周期镜像审计，不把某个结构的镜像数套给新结构。

- 输入生成前显式枚举两个目标磁性位点的超胞平移；逐壳报告选定原子对、目标距离、等距目标伙伴镜像数 $m_n$、下一近镜像距离。
- 检查自镜像、远距离伙伴像以及是否需要扩大超胞；验证非目标磁矩在四个自洽态中保持预期构型。
- 先定义哈密顿量的符号、键计数、自旋归一化以及四态能量组合。不能默认四态组合隔离一条物理键，必须按周期轨道间仍保留的相互作用求和。
- 只有证明保留模型内有 $m_n$ 条等价目标壳层键，且更远的镜像相互作用可以忽略，才使用单壳层归约。不同哈密顿量约定的符号/因子须重新推导。

## 验收与交付

分层验收：离线脚本检查 → SSH 真实登录 → 指定目录小文件写入/下载与校验 → 经授权的小规模代表作业 → 结果与已知算例核对。连接测试不冒充 VASP 验证；小规模启动检查也不冒充生产参数收敛测试。

交付说明应列出远程目录、输入变化、job ID、当前状态、科学验证结果、下载结果路径和未解决问题。
