# 服务器安全审查与实施边界

本技能只能约束 agent 的行为。拥有普通账号的 SSH shell 通常仍可操作该账号所有可访问文件；技能中的工作目录规则不是沙箱。此次审查针对技能/脚本设计，不等同于对用户真实服务器做过配置审计。

| 风险点 | 默认落实措施 | 仍需站点或用户决定 |
|---|---|---|
| 私钥泄露或公私钥错配 | 本地原生输入口令，配对检查；私钥不上传，不打印，不进入仓库/日志 | 加密磁盘、专用有口令密钥、凭据泄露后的撤销策略 |
| SSH 转发扩大访问面 | 命令行关闭 agent/X11/配置端口转发和凭据委托；新授权 key 使用 restrict | 已有 key 限制不改写；跳板机/站点功能需要单独评估 |
| 伪造服务器或主机换钥 | 独立验证 SHA256 指纹，常规 StrictHostKeyChecking=yes | 管理员确认换机/重装，不能自动接受新指纹 |
| 公钥安装破坏已有访问 | 只追加本人 key，按 key blob 去重并保留已有 options；拒绝链接、错误所有者和不安全写权限 | 集中公钥门户、非标准 AuthorizedKeysFile、NFS/ACL/SELinux 问题交站点处理 |
| 超出工作目录写入 | 授权根和最近存在父目录规范化，边界按路径组件比较；新运行目录、显式文件清单和哈希 | 独立无 sudo 的计算账号、站点目录 ACL 和调度器配额才能进一步实施隔离 |
| 上传/下载覆盖或逃逸 | 检查文件及父路径链接；新目录独占创建；下载到新本地目录，拒绝路径穿越、绝对文件名和非预期链接 | 共享可写目录的并发换链接仍有检查/使用竞态，不能宣称普通 shell 完全消除 |
| 重复计算/预算失控 | 提交前原子一次性标记，保留 submitting 状态/完整 ID；不明结果先核对；PC 同样启动锁和时限 | 真正硬资源预算由调度器/cgroup 强制；不以“估计时间”冒充硬限制 |
| 参考脚本带隐含副作用 | 执行前检查 module/source、删除、远程复制、curl、sudo、后台启动和输出位置；记录哈希 | source 的文件本身也是代码，限制在可信站点来源；不直接执行下载的一键脚本 |

SSH `restrict` 禁止转发、PTY 与用户 rc 等能力，但不限制远端 shell 可以执行哪些命令，不等于目录隔离。不要随意加 `command=` 强制命令来“加固”：它可能破坏 scp/SFTP、调度器和分析功能。更严格的强制命令网关应由管理员设计并验收。[OpenSSH authorized_keys 说明](https://man.openbsd.org/sshd)

保持现有 MFA、密码登录策略、sshd_config、防火墙、系统服务和共享软件配置不变。不要为本技能自动关闭密码认证、开放端口或启用 root 登录；这些改动可能锁住用户，且超出普通客户端搭建范围。Windows 本机 ssh-agent 服务是向导明确询问的有限例外。[Microsoft 密钥管理](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh_keymanagement)

原有可信 SSH 配置仍可能含 `Match exec`、`ProxyCommand`、`Include` 或 `KnownHostsCommand`，所以别名不是任意配置代码的隔离层。命令行硬化也不能代替配置来源审查。[OpenSSH 配置手册](https://man.openbsd.org/ssh_config)

实际服务器审计应先有读取范围，逐项核实账号权限、个人 SSH 文件元数据、工作目录 ACL/符号链接、资源配额和站点提交模板；不读取其他人的密钥/文件，不枚举全部 home，不运行 VASP 来探测登录节点。需要管理员修改的事项先给出具体差异及恢复方案，再按用户实际授权执行。
